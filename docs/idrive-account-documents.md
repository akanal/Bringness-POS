# Direct private account documents in IDrive

Owner explicitly requested using the already configured IDrive storage beyond the existing nightly backup. This adds a private PDF/PNG/JPEG account vault at /shop/documents.html. New file contents go directly to the existing Frankfurt-2 bringness-documents bucket; PostgreSQL stores only authenticated company ownership, immutable metadata, digest and object reference. Existing receipts, previews, payments, invoices, seller publications, backups and original database contents are preserved. No database is moved to object storage and no existing files are deleted or migrated by this package.

## Authorization and data path
Active owner/admin session is required before upload body ingestion, again before durable intent/provider work and before final metadata commit; downloads require the owning company before any object read and recheck after read. Cross-site access is rejected; bearer tokens never enter URLs. SDK endpoint/region/bucket are fixed in source; credentials come only from protected server configuration. AI and isolated-preview runtimes do not configure this backend. No public S3 URL/presigned URL, anonymous object read, listing of other accounts, raw provider errors or document-content logging is exposed.

AWS SDK v3 signs requests with SigV4, with bounded timeouts, one attempt, path style and optional checksums disabled unless required (matching the verified provider bootstrap). Every upload checks exact NoSuchBucketPolicy (HTTP404); an existing/unreadable policy blocks the operation. Put requires IfNoneMatch:* and SSE-AES256; readback checks exact bytes, SHA256, length, content type and bound request digest. Existing identical object after an uncertain attempt can be recovered via conditional412 plus verified readback; nothing is overwritten. Download repeats policy/read integrity checks and returns an authenticated attachment with no-store/nosniff/sandbox headers. PDF/JPEG/PNG signatures and matching filename extensions are checked; this is not a malware scanner, content approval or legal retention system.

Durable upload intents are committed before cloud work. They bind company/id/request digest and consume rolling24h allowances even on failure/revocation. Reusing the same id with changed content/name fails; identical retry remains available. Separate final transaction serializes quota and immutable metadata insertion; provider work never holds database locks. Failure may retain an unreferenced immutable object, recoverable by the identical intent; no automatic cleanup/deletion is implemented.

Limits:5MiB/file,100 files and100MiB/company,20 new intents/company per rolling24h,200 new intents globally per rolling24h and5000 committed files globally. Upload concurrency2 and download concurrency4 per app instance bound buffered memory. Raw upload body deadline15s. Quotas are server-enforced; clients cannot submit paths/company IDs/provider URLs. The browser clears private file state on account/page/privacy changes, uses an in-memory stable retry id after lost replies, and verifies downloaded bytes against SHA256 before creating a temporary download. File contents are never stored in browser localStorage/sessionStorage.

## Protected activation
Main can deploy this code with storage disabled by default; /api/v1/shop/documents/status explicitly reports configured/available. Existing forced SSH access cannot edit app secrets. A one-time owner root-console runner stages the existing private app.env with SHOP_DOCUMENT_STORAGE=idrive and the existing IDrive access ID/secret from /opt/bringness-pos/config/idrive-documents.json. It preserves all other settings, refuses conflicts/unsafe files and exposes no values. No new IDrive key or recovery passphrase is needed.

Before replacing app.env, the runner executes the new application image's explicit server/idrive-document-check.js check against real IDrive with a tiny synthetic PDF under a synthetic company namespace. It verifies signed conditional write and encrypted exact readback; the test object remains, with no real account/business record. Only then does it retain the old private environment, apply the staged file and invoke the existing unchanged deploy/pos operation for the exact reviewed revision. On failure it attempts to restore the old environment/revision. It does not alter SSH permissions, the backup timer, payment configuration or bucket policies. Public configured/available status is checked after deployment. Actual owner-console activation and real-provider SDK acceptance must be recorded separately; a CI pass is not activation.

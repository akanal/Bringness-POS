# Bringness POS remote assistance

Platform administrators use **Admin → Fernhilfe**. The device list shows Windows version, last contact, account, device status and sanitized diagnostic capabilities. A request is available only for an active device reporting support protocol 1 within two minutes. The Windows implementation is included from client 0.2.1. Existing installers do not gain native screen/input support through a website deployment.

The customer is asked in a native dialog to decline, share the POS window only, or share the POS window and permit input. Decline is the default. Requests expire after five minutes; approved sessions last at most fifteen minutes. A separate always-on-top native window provides the stop button. Closing that window, disconnecting, changing authentication, blocking a device, revoking the initiating platform membership or expiring either account session terminates access. Consent is not resumed after a desktop process restart.

Only the online Bringness application window is captured. Screenshots are refreshed about every two seconds at up to 1280 × 720 pixels and sent as bounded JPEGs over the existing authenticated HTTPS connection. The latest frame replaces the preceding frame; there is no screenshot history. Frames are removed at termination and by periodic cleanup. This is periodic image assistance, not fluid video or operating-system remote desktop.

Approved control supports click, short text, Enter/Tab/Backspace/Escape/arrows, scroll and reloading the register view. OS shortcuts, arbitrary JavaScript, terminal commands, filesystem operations and unbounded input are not accepted. The admin sends the displayed frame sequence; stale or out-of-bounds requests are rejected. Inputs are dispatched at most once. A missing acknowledgement remains explicitly uncertain and is never silently replayed. Native completion means the input was delivered to the register, not that a financial transaction succeeded. Normal POS roles, payments, fiscal gates and application validation still apply.

The initiating platform session and the customer's consenting owner/admin session are validated. Customers cannot access another company's devices or session. A platform admin is distinct from a customer's company admin. Requests, consent, actions, acknowledgements and stops record actor/device/session information in the POS audit. Text is redacted from admin history and removed from persisted commands after acknowledgement, timeout or cancellation; it is never included in audit payloads. Diagnostic data contains only app/platform/protocol/online/license flags and optional aggregate counters, not account passwords, device keys, paths or license files.

Offline sales and the local ledger are not remotely edited. If the POS window is disconnected, minimized or not authenticated with an owner/admin account, the session cannot continue. Updates remain in the existing protected download/release channel and still require a valid installation license. The new Windows artifact is unsigned unless real Authenticode secrets are configured; successful compilation does not constitute a signed public release or acceptance on a real customer's hardware.

Validation: `node server/ai-tests/remote-support.mjs` exercises the real PostgreSQL-backed authorization/consent/frame/dispatch/expiry/revocation/audit flows and the admin UI. `npx electron support-smoke.cjs` on Windows uses real native capture, scaled mouse/text input and the native stop control with a simulated HTTPS service and simulated affirmative customer consent. It never connects to a customer or creates a real support session. Real-device operational acceptance remains a separate check after installation.

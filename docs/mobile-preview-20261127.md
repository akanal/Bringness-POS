# Ordering preview: mobile and categories

Deployed only to https://sandbox-bestellen.bringness.de/bestellen/ on 2026-11-27, by applying ops/mobile-icons-20261127.py then ops/mobile-finish.py to the existing sandbox source and copying static files into bringness-delivery-sandbox-app-1. Production POS, AI and server process were not restarted. Source backup: /opt/bringness-design-backups/mobile-icons-1795793939.

Changes: dark slate backgrounds with warm text, readable form and filter controls, larger touch targets, single-column mobile search controls, bounded mobile address editor, five illustrated category icons with labels. Only restaurant ordering is available; future categories explicitly show Demnächst. Prior restaurant-highlight cards hidden; result heading retained for accessibility and existing JS.

Verified in the cloud browser: desktop screenshot; six same-origin iframe renders at nominal widths 320/390/650 (content client widths 305/375/635 due browser scrollbars). Landing and restaurant pages each reported scrollWidth equal clientWidth and zero inputs/buttons/selects extending beyond the viewport. Five categories present in all six renders. At 390px, pickup postcode 10551 submitted successfully to the separate restaurant page, returning one sandbox restaurant. A no-match restaurant query returned Keine Restaurants für diesen Filter; clearing restored one restaurant. Menu opened without horizontal overflow. At 320px, open address form stayed within viewport (left 12, right 293, viewport 305).

Test harness: /bestellen/mobile-check.html, generated by ops/mobile-check.py. No test order, payment, location permission, or customer-account mutation was performed. These are browser width checks, not physical Android/iPhone device certification. Standalone Playwright browser installation was unavailable; verification used the existing browser with same-origin frames instead. Branch contains reversible patch scripts and this evidence; no merge into production main.

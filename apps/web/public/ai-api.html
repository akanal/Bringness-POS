Zum Arbeitsbereich

Verkäufe sicher importieren.

Erstelle unter „Kassen & API“ einen Schlüssel für einen Standort. Ordne Artikelcodes den Rezepten zu und aktiviere die Anbindung. Der Schlüssel erlaubt ausschließlich Verkaufsimporte für diesen Standort.

Verkauf

POST /api/ai/import/sales
Content-Type: application/json
Authorization: Bearer DEIN_API_SCHLUESSEL

{
  "eventId": "kasse-a:verkauf-1001",
  "type": "sale",
  "items": [
    { "productCode": "gericht-42", "quantity": 2 }
  ]
}

Die eventId muss pro Anbindung eindeutig sein. Wiederhole bei Netzfehlern dieselbe ID mit denselben Daten. Der Bestand wird dadurch nur einmal verändert. Verwende je Verkaufsquelle genau eine aktive Anbindung.

Artikelcodes müssen exakt mit aktiven Rezepten dieses Standorts übereinstimmen. Mengen sind positiv und dürfen höchstens drei Nachkommastellen haben. Ein Ereignis enthält bis zu 100 Positionen. Fehlende Rezepte führen zu einem Fehler; es wird kein Teilverbrauch gebucht.

Fehlerhaften Verbrauch zurückbuchen

{
  "eventId": "kasse-a:korrektur-1001",
  "type": "reversal",
  "reversesEventId": "kasse-a:verkauf-1001"
}

Eine Rückbuchung stellt die ursprünglich gebuchten Zutatenmengen wieder her. Sie ist je Originalverkauf einmal möglich, auch wenn sich das Rezept inzwischen geändert hat. Verwende sie nur, wenn der ursprüngliche Verbrauch tatsächlich rückgängig gemacht werden soll. Eine finanzielle Erstattung allein bedeutet nicht, dass verbrauchte Zutaten wieder im Lager liegen.

Antworten und Wiederholung

200: importiert oder identische Wiederholung (duplicate: true). 400: fehlende Zuordnung oder ungültige Daten; korrigieren und erneut senden. 401/403: Schlüssel ungültig, Zugang gesperrt oder Anbindung pausiert. 409: Ereignis-ID mit abweichenden Daten oder bereits zurückgebuchter Verkauf. 503: Dienst wird vorbereitet; später wiederholen.

Halte ausgehende Ereignisse in deiner Kasse dauerhaft vor, bis der Import bestätigt ist. Wiederhole vorübergehende Fehler mit wachsendem Abstand. Eine vollständige OpenAPI-Spezifikation und anbieterspezifische Adapter folgen.

Negative rechnerische Bestände werden bewusst angezeigt: Prüfe dann Inventur, Wareneingang und Rezeptmengen. Die API blockiert keinen Kassenverkauf.

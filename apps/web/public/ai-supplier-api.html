Zum Arbeitsbereich

Dein Sortiment automatisch anbinden.

Als Händler, Großlieferant oder Hersteller kannst du Sortiment, Nettopreise und Lieferbarkeit aus deinem System übertragen. Erstelle im Arbeitsbereich unter „Lieferanten-API“ einen eigenen Schlüssel und aktiviere die Verbindung.

OpenAPI-Spezifikation herunterladen · Kassenschnittstelle

Zugang

Alle Anfragen verwenden Authorization: Bearer DEIN_LIEFERANTEN_SCHLUESSEL. Der Schlüssel erlaubt ausschließlich Zugriff auf dein Sortiment und deine Bringness-Bestellungen. Login-Token und Kassenschlüssel funktionieren hier nicht. Mit GET /api/ai/v1/supplier/status prüfst du die Verbindung.

Der Schlüssel ist nur beim Erstellen oder Erneuern sichtbar. Beim Erneuern verliert der alte Schlüssel sofort seine Gültigkeit. Pausieren sperrt die Anbindung.

Produkte übertragen

POST /api/ai/v1/supplier/products · Content-Type: application/json

{
  "requestId": "22222222-2222-4222-8222-222222222222",
  "products": [{
    "externalCode": "PATTIES-32",
    "name": "Hamburger Patties",
    "unit": "piece",
    "packQuantity": 32,
    "priceCents": 1890,
    "minimumPacks": 1,
    "active": true,
    "available": true
  }]
}

externalCode ist deine dauerhafte Artikelnummer. Gleiche Artikelnummern aktualisieren ausschließlich dein Produkt. Namen werden nicht automatisch mit bestehenden, manuell erfassten Produkten zusammengeführt. Der Nettopreis gilt je Packung. Einheiten: kg, l, piece; bei Stück sind ganze Packungsinhalte erforderlich.

Bis 100 Produkte je Anfrage werden vollständig übernommen oder gar nicht. Bei Netzfehlern dieselbe Import-ID und dieselben Daten wiederholen. Für eine neue Änderung eine neue UUID verwenden. Eine alte, bereits bestätigte Import-ID schreibt spätere Produktänderungen nicht zurück. Nicht enthaltene Produkte bleiben erhalten; zum Ausblenden active: false senden.

available: false entfernt das Produkt aus Angeboten und verhindert neue Bestellungen. Bereits übermittelte Bestellungen behalten ihre vereinbarten Preise und Packungsangaben. Verfügbarkeit ist eine Lieferbar-Kennzeichnung; sie reserviert keinen physischen Lagerbestand.

GET /api/ai/v1/supplier/products exportiert bis 100 eigene Produkte. Bei nextAfter mit ?after=ID weiter abrufen. Für einen neuen vollständigen Export ohne after beginnen.

Bestellungen übernehmen

GET /api/ai/v1/supplier/orders liefert deine Bestellungen mit Lieferadresse, Kontaktadresse und den vereinbarten Bestell- und Provisionsbeträgen. Speichere nextCursor unverändert und übergib ihn beim nächsten Abruf als ?cursor=…. Bei hasMore: true sofort weiter abrufen; ansonsten später mit demselben Cursor nach Änderungen fragen.

Die API liefert aktuelle Bestellstände, keine vollständige Statusereignishistorie. Verwende die Bringness-Bestell-ID als eindeutige Referenz in deinem System.

POST /api/ai/v1/supplier/orders/BESTELL_ID/accept nimmt eine gesendete Bestellung an. POST /api/ai/v1/supplier/orders/BESTELL_ID/cancel storniert eine noch offene Bestellung. Wiederholte identische Aktionen buchen nicht doppelt. Bereits bestätigte Wareneingänge können nicht über diese API storniert werden. Den tatsächlichen Wareneingang bestätigt ausschließlich das Restaurant.

Provision und Fehler

In beiden Einführungsmodellen trägt der Lieferant 2 % des vermittelten Netto-Warenwerts. Preis- und Provisionsbeträge werden bei Bestellung gespeichert. Die API kann diesen Satz weder ändern noch Zahlungen als beglichen markieren. Eine offene, stornierte Bestellung hat keine Provision. Automatische Abbuchung ist hier nicht enthalten.

400: Eingabe korrigieren. 401/403: Schlüssel, Aktivierung oder Konto prüfen. 404: Funktion oder eigene Bestellung nicht gefunden. 409: Import-ID mit anderen Daten oder unzulässiger Bestellstatus. 429: Limit erreicht. 500/503: vorübergehender Fehler. Bei 429/500/503 mit wachsendem Abstand wiederholen. Limit: 600 Anfragen je Verbindung in 15 Minuten.
